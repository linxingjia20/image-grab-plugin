# 电商图片采集助手

一个基于 Chrome Manifest V3 的电商图片采集扩展。在淘宝 / 天猫、京东、拼多多（含商家后台）商品详情页右下角悬浮「获取图片」按钮，一键扫描页面图片，过滤小图标，集中展示并可勾选批量下载为 PNG。

## 功能

- 商品详情页右下角悬浮按钮，自动识别路由变化（适配 SPA 页面）。
- 扫描 `<img>`、`srcset`、常见 `data-*` 懒加载属性、`<video poster>`、SVG `<image>`、`<input type="image">`。
- 扫描元素 CSS `background-image` 背景图，并按元素的 `background-size` 过滤小尺寸背景图标。
- 自动滚动页面触发懒加载图片，扫描完成后恢复原始滚动位置。
- 自动升级常见 CDN 图片地址，尽量获取原图：
  - 阿里 CDN：去除 `_800x800q90.jpg`、`_.webp` 等尺寸后缀。
  - 京东 CDN：`n1` / `s450x450_*` 等路径切换为 `n0`。
  - 拼多多 CDN：去除 `imageView2` / `imageMogr2` 缩放参数。
- 按展示尺寸 / 原始尺寸过滤小图标、占位图、透明像素。
- 扫描结果在新标签页集中展示，支持：
  - 全选、反选、按「普通图片 / 背景图」筛选。
  - 网格预览、大图预览、打开原图。
  - 勾选后批量转换为 PNG 下载。
- 所有图片处理在本地完成，不上传到任何服务器。

## 安装

1. 打开 Chrome 的 `chrome://extensions/`。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本目录。
4. 打开任意支持的商品详情页，页面右下角会出现「获取图片」按钮。

要求 Chrome 102 或更高版本。

## 使用

1. 进入淘宝 / 天猫、京东、拼多多商品详情页。
2. 点击右下角「获取图片」。
3. 等待扫描完成，图库会在新标签页打开。
4. 勾选需要的图片，点击「下载 X 张为 PNG」。
5. PNG 文件默认保存到：
   `下载目录/ecom-images/<站点>/<日期>/`

点击扩展工具栏图标，可以再次打开最近一次采集结果。

## 隐私与数据

- 图片扫描、PNG 转换全部在本地浏览器中完成，不会上传到任何服务器。
- 扫描结果只保存在 Chrome 的 `chrome.storage.local` 中，最多保留最近 6 次记录；空间不足时会自动清理更早的记录。
- 扩展只读取当前页面公开 DOM 中的图片地址、尺寸和背景样式，用于生成图库；这些数据不会上传。
- 所有脚本随扩展打包，不加载远程代码。
- 不再使用时，可以在 `chrome://extensions/` 中移除扩展，浏览器会同时清理扩展本地数据。

## 文件结构

```
manifest.json      MV3 清单
background.js      Service Worker：保存扫描结果、打开图库
content.js         页面扫描、悬浮按钮、懒加载触发
content.css        Shadow DOM 内的悬浮按钮样式
gallery.html       图库页面
gallery.js         选择、预览、PNG 转换与批量下载
gallery.css        图库样式
icons/             扩展图标
```

## 实现说明

### 页面采集

`content.js` 只在检测到商品详情页时挂载 UI，使用 Shadow DOM 隔离站点样式。点击按钮后会：

1. 按视口高度分步滚动页面，触发 IntersectionObserver / 懒加载逻辑。
2. 每一步收集一次图片，避免虚拟列表或轮播切换导致图片丢失。
3. 如果窗口本身不可滚动（常见于拼多多商家后台），会尝试滚动页面内最大的可视滚动容器。
4. 等待图片加载完成，再扫描 CSS 背景图。
5. 对 URL 做标准化、原图升级、去重和尺寸过滤。
6. 通过 `chrome.runtime.sendMessage` 将结果交给 Service Worker。

扫描最多保留 800 张图片，避免超大页面拖慢浏览器。

### PNG 转换与下载

图库页面使用 `fetch` 获取图片二进制，再用 `createImageBitmap` / `<img>` + `<canvas>` 转成 PNG，最后通过 `chrome.downloads.download` 下载 Blob URL。

- 并发数限制为 2，降低内存峰值。
- 超大图片会等比缩小到画布限制内（最大边 8192px / 约 3200 万像素），并在完成提示中说明。
- 转换失败时会尝试原始 URL，仍失败则标记该卡片为「下载失败」。
- 页面关闭前如果有下载任务，会触发离开确认，避免 Blob URL 被提前释放。

### 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存最近几次扫描结果 |
| `downloads` | 批量下载 PNG |
| 目标站点 host 权限 | 注入内容脚本、读取商品页 |
| 常见 CDN host 权限 | 跨域读取图片并转换为 PNG |
| `optional_host_permissions: *://*/*` | 仅当图片来自未知第三方图床时，按需向用户申请该域名的读取权限 |

扩展不会在未授权的站点注入脚本；内容脚本只匹配清单中列出的电商域名。

## 已知限制

- 不扫描 iframe / Shadow DOM / `<canvas>` 内部图像。
- 受防盗链、登录态或跨域权限保护的图片可能无法读取；图库会标记失败。
- 视频本身不会被下载，仅采集 `<video poster>` 封面。
- 超长页面滚动扫描有步数上限（36 步），极端页面可能只采集到部分图片。
- 图片地址来自页面公开 DOM，若站点使用加密 / 混淆地址或先加载占位图，可能无法还原原图。
- 批量下载会创建多个独立 PNG 文件，不会自动打包 ZIP。

## 常见问题

### 为什么详情页没有出现「获取图片」按钮？

- 确认当前页面是商品详情页，而不是首页、搜索结果或购物车。
- 扩展只在桌面版 Chrome 中运行，并且需要 Chrome 102+。
- 如果是刚安装扩展或刚修改过代码，请刷新商品页；修改 `content.js` 后尤其需要刷新。
- 部分站点使用特殊路由，扩展会每 1.5 秒重新检测一次 URL；如果仍未出现，可以打开 `chrome://extensions/` 确认扩展没有报错。

### 为什么扫描时页面会自动滚动？

很多电商详情页使用 IntersectionObserver 懒加载，不滚动到图片位置，图片地址就不会写入 DOM。扫描完成后会自动回到原来的滚动位置。

### 为什么图片数量比页面看到的少？

- 小于约 120 × 60 的图标、占位图、透明像素会被过滤。
- 扫描最多保留 800 张图片。
- iframe、Shadow DOM、`<canvas>` 内的图片不会被扫描。
- 虚拟列表、需要登录后才能加载的图片可能无法完整采集。

### 为什么部分图片下载失败？

- 图片 CDN 可能有防盗链、Referer 或登录态限制。
- 图片来自未授权的第三方图床时，Chrome 会请求一次域名访问权限；如果拒绝，该域名下的图片可能无法读取。
- 图片格式浏览器无法解码，或图片超过 60MB，也会失败。
- 失败的卡片会显示「下载失败」，可以重新勾选后重试。

### 下载的图片一定是 PNG 吗？

是。每张图片都会先读取二进制，再通过 Canvas 重新编码为 `image/png` 后下载；即使原图是 JPG、WebP 或 AVIF，最终文件也会是 PNG。

### 关闭图库页面会怎样？

如果还有下载任务，浏览器会弹出离开确认。请等待「下载完成」提示出现后再关闭页面，否则尚未完成的 Blob URL 可能失效。

## 开发

无需构建步骤，修改文件后在 `chrome://extensions/` 点击扩展的「重新加载」即可。修改 `content.js` 后需要刷新目标商品页。

静态校验命令：

```bash
node --check content.js
node --check background.js
node --check gallery.js
node -e "JSON.parse(require('fs').readFileSync('manifest.json','utf8'))"
```

项目没有第三方运行时依赖，也不需要打包工具。
